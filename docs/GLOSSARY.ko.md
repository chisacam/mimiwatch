# 채널별 시어집 (Channel glossary)

Status: Accepted | Tier: local (user override) | Date: 2026-09-08

*[English](GLOSSARY.md)*

## Context

장르 프롬프트(`translate.py`의 `GENRE_PROMPTS`)는 발화의 *성격*을 고릅니다 —
라이브 잡담과 튜토리얼은 다른 톤을 원하니까요 — 하지만 *고유명사*를 못
고정합니다. 방송자 이름, 브랜드, 유행어는 매번 다른 번역이 됩니다. 모델에게
그게 무엇인지 알려주는 곳이 없고, 참조할 목록도 없기 때문입니다. 라인은 이웃
몇 라인의 맥락만 들고 혼자 번역되기에, 10번째 줄의 "김의 방송"이 90번째 줄엔
"키 야크 채널"이 됩니다.

시어집이 그 목록입니다. `원어 → 번역` 쌍의 묶음이고, 당연히 **채널 단위**
입니다. 채널의 고유명사는 그 채널의 방송을 관통해 안정적이고, 서버가 URL에서
이미 파서내는 단위가 채널이기 때문입니다(`live.site_of`: YouTube
`channel_id`, Twitch 로그인명, 그 외 빈 값).

## Decision

1. **저장.** `store.py`에 `glossaries` 테이블 추가: `channel_key`(기본
   키), `name`(UI에서 보이는 이름), `terms`(`{"from", "to"}` 쌍의 JSON
   리스트), `updated_at`. `channel_key`는 추출된 채널이면 `"{site}:{id}"`
   (`youtube:UC…`, `twitch:login`), 이름을 지운 채널이면
   `"manual:{name}"`입니다. 시어집은 `backends.json`에 넣지
   않습니다(그 파일은 `config.py`의 전유물). 다른 사용자 데이터처럼
   `data/mimiwatch.db`로 갑니다.

2. **연결.** `/api/probe`는 이미 `live.site_of`에서 받은 채널을 돌려주지만,
   프론트는 아직 그것을 job 메타에 싣지 않습니다 — 싣게 될 것입니다. 추가
   흐름이 추출된 채널을(추출이 빈 값이면 — 로컬 파일, 그 외 사이트 — 사용자가
   친 이름과 함께) job/세션 메타에 저장합니다. 번역이 시작될 때 루프가 그
   채널 키로 시어집을 찾습니다. 채널이 아무것도 가리키지 않는 job은 아무것도
   일치하지 않고, 그것은 조용히 사라지지 않고 표시됩니다.

3. **전달: 프롬프트만.** 쌍이 있으면 번역기가 프롬프트 뒤에 렌더된 블록을
   붙입니다. 예: "Translate using this glossary as-is: A → B, C → D"
   (최종 문구는 UI 문자가 아니라 `translate.py`의 상수). 프롬프트를 쓰지
   않는 백엔드(M2M-100)는 블록을 통째로 무시합니다. 오늘은 UI에서 이를 말하는
   곳이 없습니다 — 장르 힌트는 프롬프트가 *무엇을 하는지*를 설명할 뿐
   (translate.py)이고, M2M의 사실은 코드 주석에 있습니다. 엔진 힌트와 시어집
   화면이 싣게 될 경고는 새 일입니다(아래 §Consequences). v1에는 사후 문자
   치환이 없습니다(고려하고 보류; 아래 참조).

4. **범위: 이후 라인만.** 시어집을 고쳐도 이미 번역된 라인을 다시 스캔하지
   않습니다. 기존 전체/부분 재번역 job이 그 변화를 적용하는 도구이고, 그
   경로는 최신 쌍을 다시 읽습니다.

5. **UI.** Engines 다이얼로그에 "채널 시어집" 버튼. 여는 화면은 하나: 채널
   목록(이름, 쌍 수)과 편집기 — 1줄에 `A → B`, 화살표는 UI가 치거나
   넣어주고, 첫 `→`에서 쪼개집니다. 저장하면 버스에 `glossary` 이벤트를
   내보내 이미 열린 창이 목록을 새로고침합니다.

6. **API.** `server.py` 라우팅 테이블에 두 루트: `GET /api/glossaries`(목록)
   와 `PUT /api/glossaries`(본문: `channel_key`, `name`, `terms`; 생성하거나
   갱신 — 빈 `terms`는 행 삭제).

## Options considered

- **A — 채널을 1급 개체로 (채택).** 추출된 채널로 키를 잡고 job에 자동으로
   연결하는 스토어 테이블. 내어주는 것: 새 테이블, 두 루트, UI 화면 하나,
   시어집이 붙아 있는 동안 매 라인의 프롬프트 토큰.
- **B — 비디오 단위 용어, "채널로 저장".** 용어가 장르처럼 job 메타에 있고,
   채널 저장소로 복사하는 액션. 거절: 저장이 비디오마다 한 번의 노동이라
   목표의 본질을 깎습니다 — 핵심은 그 채널의 두 번째 방송이 공짜가 된다는
   것인데.
- **C — A의 저장소 + 수동 연결만.** 거절: "매번 채널 고르기"는 이 기능을
   그 크기에 값지게 만드는 "두 번째부터 수고 없음" 성질을 빼버립니다.
- **전달 메커니즘** (원래의 갈림): 프롬프트 주입만(채택), 사후 문자
  치환, 둘 다. 치환은 M2M-100에서도 성립하지만 형태소 굴절과 한자 표기
  변형에 약하고, 일관시켜야 할 메커니즘이 둘이 됩니다. 보류의 비용은
  없습니다: 쌍으로 저장되어 있으니 치환 패스는 데이터 변경 없이 나중에
  붙일 수 있습니다.

## Consequences

- **프롬프트 토큰이 시어집 크기로 자랍니다.** 매 라인이 블록을 실어
  넘습니다. 렌더된 블록은 앞의 100쌍으로 잘립니다(아래 가드레일). 캡을
   넘어도 *저장*은 전부를 하고, 잘리는 것은 렌더 부분뿐입니다.
- **M2M-100 사용자는 시어집 화면을 열어도 그에게 아무것도 하지
   않습니다.** 경고를 엔진을 고르는 자리, 이미 "프롬프트는 프롬프트
  백엔드 전용"이라 말하는 장르 힌트 옆에 두어야 합니다.
- **채널 id의 안정성은 미측정입니다.** YouTube 영상 URL과 같은 스트림의
   재방송이 같은 `channel_id`로 갈지 확인하지 않았습니다. 가드레일 —
   job 진행 줄이 적용된 시어집(이름, 쌍 수) 또는 "없음"을 찍는 것 — 이
   실패를 조용한 것이 아니라 보이는 것으로 만듭니다.
- **라이브 세션도 얻지만, 공짜는 아닙니다.** 라이브 큐는
  `jobs._translate_rows`가 아니라 `live.py`의 자체 발화 단위 루프
  (`_translate_loop`)에서 번역됩니다 — 그 루프의 "세 경로"는 VOD 쪽 셋이고,
  `live.py`는 `jobs`를 import할 수 없습니다(순환이 되기 때문). 라이브에 블록을
  전달하려면 `live._translate`를 고치는 일이고, 채널은 세션 시작 때 알려져
  있어 변경은 작습니다. v1은 둘 다 포함합니다.

## Constraints for implementation

**Required**

- VOD 경로의 번역 루프는 하나(`jobs._translate_rows`): 시어집은 거기에서
  풀어 `mw_translate.build(spec, genre, glossary)`로 넘깁니다. 라이브 경로는
  `live.py`의 별도 루프이고, 블록은 같은 번역기 객체를 통해 도달합니다.
  *새* 번역 경로는 없습니다 — 시어집은 기존 경로가 렌더하는 데이터입니다.
- 추가 흐름이 채널(추출, 또는 수동 이름)을 job/세션 메타와
  `/api/transcribe` 본문에 싣습니다.
- 새 UI 라벨은 문자열표에, 이 문서가 인용한 라벨은 `bench/docs_check.py`
  선정 목록에 추가합니다.
- 새 루트는 `server.py` 라우팅 테이블(정확한 dict + 접두어 목록)에,
   if-체인에 넣지 않습니다.
- UI 문자열은 문자열표로, 영문·한국어 쌍으로.
- 스토어는 `store.py` 패턴(`_write`/`_rows`, `init()`에서의 마이그레이션).
- 테스트: 모델 없음, `isolated` 픽스처. 최소: 빈 시어집이 오늘과
  바이트 동일한 프롬프트를 만드는가; 쌍이 있으면 블록이 렌더되는가;
  `live.site_of` 출력(youtube, twitch, file, other)과 수동 이름에서
  채널 키를 도출하는가; 스토어 왕복; 두 루트 등록; live cue 프롬프트가
  쌍이 있으면 블록을 싣는가; 전사 요청 본문에 채널 키가 실리는가.
- `docs/GLOSSARY.ko.md` 동반 문서를 이 파일과 함께 편집.
- v1에는 `ext/` 변경 없음 — 확장 기능이 시어집을 읽거나 쓰지 않습니다.

**Forbidden**

- v1에서 번역 출력의 사후 문자 치환.
- `backends.json`이나 `config.py` 경로의 시어집 저장.
- 기존 장르 프롬프트 문구 수정(시어집은 붙는 것이지 엮이는 것이
  아님).
- 시어집이 바뀌었을 때 이미 번역된 라인을 다시 스캔.

**Guardrails**

- 빈 시어집 경로는 변경 전 동작과 바이트 동일한 프롬프트를 만들어야
  합니다 — 그 비교가 회귀 테스트입니다.
- 렌더 블록은 앞의 100쌍으로 캡.
- job 진행이 적용된 시어집(이름, 쌍 수) 또는 "없음"을 표시.
- 시어집 저장·삭제는 버스에 `glossary` 이벤트를 내보냄.

## Verification

- **유닛(모델 없음).** 스토어 왕복; YouTube 영상 URL, Twitch URL, 로컬
  파일(수동 이름), 알 수 없는 사이트의 키 도출; 렌더 — 쌍 있으면 블록
  있고, 없으면 바이트 동일; M2M 계열 spec의 `build`는 쌍을 무시.
- **목 통합.** OpenAI 호환 목이 요청을 기록; 3쌍 시어집의 VOD job은 모든
  프롬프트에 블록을 싣고, 편집 뒤 재번역 job은 새 쌍을 싣습니다.
- **수동.** 5쌍 시어집의 실방송: 고유명사 하나가 50여 줄을 관통해
  안정. M2M-100 런에서 미적용 경고가 보이고, 쌍을 고쳐 재번역하면
  적용됩니다.
- **문서.** 이 문서가 인용한 새 UI 라벨은 문자열표와
  `bench/docs_check.py` 선정 목록에 있고, 게이트가 한 쌍을 대조합니다.
